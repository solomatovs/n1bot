# pg-search-lab: страница проверки поисковой выдачи

Минимальный стенд: одна страница с полем запроса и три колонки результатов (fts, trgm,
vector) поверх схемы `ix`. Нужен, чтобы подбирать поисковые запросы и ранжирование на живых
данных. Не часть приложения.

```
.venv/bin/python docs/pg-search-lab/server.py \
    --dsn "host=... dbname=... user=... password=..." \
    --cache-dir compose/chainlit/models/fastembed \
    --port 8700
```

Дальше http://127.0.0.1:8700/ или через nginx по /boba-search/ (location в
/app/docker/compose/nginx/conf.d/locations/boba.conf проксирует на хост, порт 8700; сервер тогда
запускается с `--host 0.0.0.0`). Ключи: `--host`, `--port`, `--model`, `--dim`, как у
`pg-indexer-vector`; вектор запроса считает тот же провайдер проекта (`embed_query`,
префикс `query:`).

Запросы лежат в `sql/fts.sql`, `sql/trgm.sql`, `sql/vector.sql` и читаются на каждый поиск:
правки ранжирования видны без перезапуска. Контракт: именованные параметры `%(q)s`,
`%(limit)s`, для вектора ещё `%(v)s`; результат это колонки `surface`, `address` (jsonb),
`score`, `aspect`, `snippet`. Страница показывает адрес, вид, аспект, счёт и сниппет.
Ошибка SQL приходит в колонку текстом, сервер при этом не падает.

Подсказки при наборе включаются галочкой «подсказки»: через 0,5 с после остановки набора
страница спрашивает режим `suggest` (`sql/suggest.sql`: префикс имени или пути по btree с
`varchar_pattern_ops`, затем похожие слова по триграммам с порогом 0.4) и показывает список
под полем; клик по пункту подставляет его текст и запускает полный поиск, Enter ищет
набранное, Escape прячет список.

Что сейчас в запросах: fts суммирует ранги строк node по всем аспектам и берёт сниппет
из лучшей; trgm считает `word_similarity` по name, words и path с порогом 0.3; vector
берёт ближайшие чанки и ранжирует node по лучшему из них.
