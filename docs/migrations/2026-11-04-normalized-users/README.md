# SQL-версия 0002: нормализованные пользователи

Таблица `users` содержит `id`, `created_at`, обязательный `login`.
Ограничение `users_login_key` делает `login` уникальным.
Проверка `users_identity` задаёт допустимый формат этих полей. Строковый
`identifier` вычисляется в коде; отдельной колонки нет.

Версия `0002` есть у AID, MCP, CLI Boba и пакета `boba.identity_postgres`.
Каждая папка SQL полностью описывает целевые объекты. Команда исполняет
только выбранную папку, без определения исходной версии и промежуточных шагов.
Версия `0001` остаётся отдельным описанием структуры, доступным для явного выбора.

```sh
boba-aid migrate --config /etc/boba/aid.toml --migration-version 0002
boba-mcp migrate --config /etc/boba/mcp.toml --migration-version 0002
boba migrate --config /etc/boba/agent.toml --migration-version 0002
```

`--database` и `--schema` задают место применения. Без них используются
настройки подключения и схемы из конфига. База должна существовать;
отсутствующая схема создаётся командой.

SQL сравнивает объявленные таблицы с временными моделями выбранной версии.
Он создаёт отсутствующие таблицы и приводит колонки, ограничения, индексы,
комментарии и определения последовательностей к модели. Другие таблицы
схемы не удаляются и не используются для определения её версии.

Скрипты не читают прежний `users.meta`, не разбирают `identifier`, не создают
пользователей из истории и не импортируют роли, членство или MCP endpoints.
Значения последовательностей не пересчитываются по содержимому таблиц.

Если существующие строки или внешние зависимости мешают применить DDL,
PostgreSQL возвращает ошибку и транзакция компонента откатывается.
Автоматического заполнения, сопоставления или удаления таких строк нет.
