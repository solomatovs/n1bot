# Перенос истории чата в историю агента

Раньше беседу треда хранил чекпойнтер langgraph, теперь её хранит агент в таблице
`history_records`. Скрипт `migrate.sql` один раз переводит все треды, найденные в
чекпойнтах, в сессии агента с тем же id и записывает каждому треду чата ключ
`threads.meta.agent_session`: только по нему чат находит сессию треда. Чекпойнты
только читаются. `rollback.sql` отменяет перенос.

Схемы чекпойнтов, истории агента и чата должны лежать в одной базе.

## Переменные psql

| переменная | что это | пример |
|---|---|---|
| `checkpoints_schema` | схема чекпойнтов langgraph | `checkpoints` |
| `history_schema` | схема истории агента, `[agent.history].schema` конфига чата | `agent_history` |
| `chainlit_schema` | схема данных чата (`threads`, `elements`) | `chainlit` |
| `chat_url` | адрес чата глазами агента, `[agent].public_url` | `https://chat.example.com/boba` |
| `version` | метка в поле `version` перенесённых записей, по ней откат находит перенесённое | по умолчанию `history-migrate-2026-10` |

Первые четыре обязательны, `rollback.sql` берёт `history_schema`, `chainlit_schema` и
`version`.

## Что получается

- Каждый тред становится сессией агента с тем же id; вопросы, ответы, вызовы и итоги
  инструментов, ошибки модели и прерванные ответы переводятся в записи агента.
- Вложение вопроса получает ссылку `resource_link` на маршрут canvas чата, если файл
  лежит в каталоге своего треда (`…/<id треда>/upload/<имя>` или `…/mermaid/<имя>`):
  этот маршрут его отдаст. Файл вне каталогов треда, например `/workspace/upload/<id>`
  старой раскладки, маршрут не отдаёт, поэтому ссылки у него нет, а его имя остаётся в
  тексте вопроса как `[@имя]`. Такие вложения скрипт перечисляет в заметках.
- Тред, который чат уже привязал к другой сессии агента, не переносится: беседу в нём
  уже ведёт агент. Скрипт выводит такие треды списком.
- Тред без строки в `threads` переносится, но чат его не покажет; скрипт выводит их число.

Весь перенос — одна транзакция. Если тред нельзя перевести (id не годится в id сессии
или сообщения записаны не в msgpack) или сверка нашла расхождение, скрипт
останавливается с перечнем причин и ничего не меняет. Повторный запуск ничего не
дублирует: сессию, которая уже есть в истории, он пропускает.

## Порядок действий

1. Выкатить вместе с переносом версию чата и агента из этой ветки: агент хранит
   вложения вопросов блоками `resource_link`, а чат находит сессию треда только по
   `agent_session`. Без переноса старые треды в ней откроются пустыми.
2. Остановить чат, чтобы во время переноса никто не открыл старый тред и не задал в
   нём вопрос.
3. Сделать дамп затронутых схем:
   `pg_dump -d <база> -n chainlit -n checkpoints -n agent_history -Fc -f before-history.dump`
   (схемы `agent_history` может ещё не быть — тогда без неё).
4. Запустить перенос:
   ```sh
   psql -d <база> -v checkpoints_schema=checkpoints -v history_schema=agent_history \
        -v chainlit_schema=chainlit -v chat_url=https://chat.example.com/boba \
        -f migrate.sql
   ```
   Посмотреть вывод: заметки перевода, число тредов без строки в `threads`, итог
   (`sessions_loaded`, `records_loaded`, `threads_bound`) и строку
   `The migration is committed.`
5. Запустить чат и открыть несколько старых тредов: с вложением, с прерванным ответом,
   с итогами инструментов и с ошибкой модели.
6. Если что-то не так, до продолжения бесед откатить перенос:
   ```sh
   psql -d <база> -v history_schema=agent_history -v chainlit_schema=chainlit -f rollback.sql
   ```
   Если в перенесённых сессиях уже есть новые записи агента, откат остановится, ничего
   не тронув, и выведет эти сессии. Тогда вернуть состояние можно только из дампа.
