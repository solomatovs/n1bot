# cfl-indexer: Confluence в граф ix

Скрапер и индексатор Confluence одним компонентом. Идёт по спейсу страница за
страницей, на каждом объекте обновляет node, tree, surface-строку и все три индекса
`cfl_idx_*`; оригиналы (HTML страницы, файлы вложений) не хранятся — только их хэши.
Со скрапером PostgreSQL и индексаторами `pg-idx-*` не связан: у Confluence свои
поверхности и свои таблицы индексов.

```
schema/        DDL: значения surface_e и aspect_e, словари, поверхности cfl_*, индексы, объявления
run/           SQL шагов обхода: node, tree, surface-строки, индекс node, вектор, чистка
confluence.py  чтение Confluence: спейс, списки, тело, markdown, вложения и хэши оригиналов
documents.py   вердикт по вложению и текст его файла: кодировки, liteparse, OCR
store.py       запись в ix: node, tree, surface-строки, индекс node, чистка спейса
worker.py      конфиг, обход спейса, воркеры, CLI
```

## Установка

Ядро ставится пакетом `pg-ix-core`, дальше схема этого пакета своей командой:

```
.venv/bin/boba-ix-core upgrade --config ../../compose/apps/pg-ix-core/conf.toml
.venv/bin/boba-cfl-indexer upgrade --config ../../compose/apps/cfl-indexer/conf.toml
```

Конфиг приложения на dev-стенде лежит в `compose/apps/cfl-indexer/conf.toml` (каталог
вне git, в нём креды). Пути в конфиге пишутся от `${env.base}` — каталога, где лежит
файл. Секция `[ix.cfl_indexer]`: база ix (`db_schema`, `postgres`, `krb`), модель
эмбеддинга (`cache_dir`, `model`, `dim`, `chunk_tokens`, `chunk_overlap`), список
`sources` — по записи на сервер Confluence с именем, `spaces` и endpoint
(`confluence.profile` — web-профиль с auth или без, `confluence.body_format`,
`confluence.dump` — дамп HTTP-обмена), `workers`, вложения (`attachments` — маски
имён и media-type, `text_encodings`, `ocr_enabled`, `ocr_language`, `tessdata_path`,
`max_pages`, `num_workers` OCR) и `weights` полнотекста по имени аспекта.

```toml
[[ix.cfl_indexer.sources]]
    name   = "cwiki"
    spaces = ["ATTIC", "BVAL"]

    [ix.cfl_indexer.sources.confluence.profile]
        scheme = "https"
        host   = "cwiki.apache.org"
        port   = 443
        path   = "/confluence"
```

## Запуск

```
.venv/bin/boba-cfl-indexer run --config ../../compose/apps/cfl-indexer/conf.toml [--source cwiki] [--space DEV] [--reindex]
```

`--source` ограничивает прогон одним сервером, `--space` — одним спейсом (при
нескольких источниках вместе с `--source`). `--reindex` на один прогон отключает
отсечение по версии и хэшу параметров: всё перечитывается и переиндексируется без
правок конфига и кода; вектор при этом всё равно пересчитывает только аспекты, чей
текст изменился.

Один спейс обрабатывает один воркер строго последовательно; `workers` — сколько спейсов
идёт параллельно, каждому нужно своё соединение, поэтому `postgres.pool.max_size` не
меньше `workers`. Эмбеддер один на процесс.

## Что делает обход

1. `GET /space/{key}` — node спейса, `cfl_space`, аспекты `title`, `words`, `card`.
2. Списки `space/{key}/content/page` и `/blogpost` с версиями, предками, метками и
   историей, без тел. На каждом объекте: node по адресу, tree по последнему предку,
   отметка «увиден» в temp-таблице сессии.
3. `version` и `indexer_hash` совпали с surface-строкой — дальше ничего. Иначе тело
   `body.view`: `content_hash` = sha256 исходного HTML, в индекс идёт markdown.
4. Транзакция: surface-строка; строки триграмм и полнотекста node снимаются; `body`
   кладётся в полнотекст из Python; `title`, `path`, `words`, `labels`, `card`
   выводятся из объявлений `surface_aspect` этого же пакета и раскладываются по
   полнотексту (вес из конфига) и триграммам.
5. Вектор: аспекты класса `description` сверяются по md5 с записанными чанками, модель
   считает только изменившиеся, чанки исчезнувших аспектов снимаются.
6. Вложения страницы: из раскрытия списка, при усечении — полным списком. Node, tree
   под страницей и surface-строка пишутся всегда, так что файл находится по имени и
   пути; текст — только у взятых. Берётся ли файл, решают маски `attachments` и флаг
   `ocr_enabled` (картинки без OCR не качаются); неподдерживаемый тип остаётся
   метаданными. Файл льётся во временный каталог с sha256 по дороге, текст
   извлекает liteparse (pdf, office, картинки с OCR) или декодирование по
   `text_encodings`; у картинки текст идёт аспектом `ocr`, у остального — `body`. Если
   версия сменилась, а байты нет, файл не разбирается заново: прежний текст берётся
   из полнотекста. Файл, который не разобрался, считается в `failed` отчёта и не
   останавливает спейс; команда завершается с ошибкой, если такие были.
7. Комментарии страницы: `content/{id}/child/comment` с телами — у страницы нет
   признака, что комментарии менялись, поэтому список читается на каждом обходе
   (один запрос на страницу). Node под страницей, `cfl_comment` с местом (inline или
   footer), автором и датами, текст — markdown тела, `card` — «Comment by …».
8. Ссылки: из тела каждой перечитанной страницы снимаются ссылки на другие страницы
   (по id, по заголовку, макросом `ri:page`) и копятся в temp-таблице сессии. После
   обхода они разрешаются в node — по id через адрес сервера, по заголовку через
   `cfl_page` этого спейса — и становятся рёбрами `edge` с поверхностью
   `cfl_page_link`; прежние рёбра перечитанных страниц снимаются, страницы без
   изменений свои рёбра сохраняют. Внешние ссылки и ссылки на себя отбрасываются.
9. Конец спейса: node спейса, которых прогон не видел, удаляются вместе со строками
   индексов; рёбра ушедших node снимает каскад.

`indexer_hash` — md5 параметров преобразования и модели (формат тела, стиль markdown,
модель, окно чанков, веса, маски вложений, кодировки, OCR, версия раскладки). Смена любого переводит все объекты
спейса в переиндексацию с повторным скачиванием: цена решения не хранить оригиналы.

## Аспекты

| aspect | класс | поверхности | что это |
|---|---|---|---|
| title | ident | space, page, blogpost, attachment | заголовок, имя файла или спейса как есть |
| path | ident | page, blogpost, attachment | `DEV/Заголовок` |
| words | words | space, page, blogpost, attachment | слова заголовка, как у pg |
| labels | description | page, blogpost | метки через пробел |
| card | description | все | карточка: вид, путь, метки, начало текста |
| body | description | page, blogpost, attachment, comment | полный текст, пишет индексатор |
| ocr | description | attachment | текст с картинки или скана |

Объявления в `surface_aspect` нужны не только самому индексатору: описатель и другие
потребители объявят поверх них свои аспекты (`describer_input`, `llm_description`).

## Адреса

Частями, как у postgres: спейс `{scheme, host, port, space}`, страница и блог-запись
`{scheme, host, port, content}`, вложение и комментарий добавляют `attachment` или
`comment`; Confluence под префиксом пути (`/confluence` у cwiki.apache.org) несёт ещё
`path` — это другой сервер на том же хосте. Ссылка для человека собирается из адреса; область спейса для чистки —
`space_key` поверхностей.

## Тесты

`tests/` — интеграционные: заглушка Confluence из `boba.stand.confluence` (граф, три
индекса, отсечение по версии и хэшу, чистка) и живой спейс стенда. Нужны `[ix_stand]`
с `embedding_cache_dir` и `[site]` с токеном Confluence в `stand.toml`.
